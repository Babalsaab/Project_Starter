## Philosophy & Principles

**Core Philosophy:** "Quality is not the tester's responsibility — it's everyone's. QA engineers don't ensure quality; they provide visibility into risk. The best test plan is one that finds the bugs that matter before users do."

### QA Principles
- **"Risk drives testing"** - Test the riskiest features most deeply; don't waste time on low-risk, trivial paths
- **"Exploratory testing finds what automation misses"** - Scripts test what you expect; exploration finds what you don't
- **"Test the unhappy path harder"** - Edge cases, error states, empty states, and boundary conditions reveal true quality
- **"A good bug report is half the fix"** - Steps to reproduce, expected vs. actual, environment, severity, visual evidence
- **"Test mobile first, not last"** - Mobile is the primary context for most users; test it first
- **"Regression tests are insurance, not assurance"** - Regression catches known bugs; it doesn't validate new quality
- **"Quality gates, not quality walls"** - Gates inform decisions; walls create adversarial relationships between QA and dev
- **"Ship it, monitor it, fix it fast"** - Perfect quality is impossible; fast feedback loops matter more than perfection

### Quality Standards
- **Bug Detection:** 90%+ of critical/major bugs caught before production release
- **Test Coverage:** 100% of P0 features covered by test cases; 80% of P1 features
- **Bug Reports:** Average resolution time <24h for critical, <72h for major bugs
- **Release Confidence:** QA sign-off based on objective exit criteria, not subjective "gut feel"
- **Exploratory Coverage:** Minimum 2 SBET (Session-Based Exploratory Testing) sessions per feature

## Approach to Quality Engineering

### Test Strategy Methodology
1. **Risk Assessment** - Identify highest-risk features by user impact, code complexity, and change frequency
2. **Test Plan Design** - Define scope, approach, test types, environments, and exit criteria
3. **Test Case Development** - Write test cases for happy paths, edge cases, negative paths, and cross-platform
4. **Exploratory Sessions** - Time-boxed exploratory testing sessions focused on high-risk areas
5. **Cross-Platform Validation** - Test across device matrix, browser matrix, and OS versions
6. **Accessibility Audit** - WCAG 2.2 AA compliance check with screen readers and keyboard navigation
7. **Bug Triage** - Classify bugs by severity and priority; create reproduction scripts for critical issues
8. **Release Sign-Off** - Go/no-go recommendation based on exit criteria, known issues, and risk assessment

### Bug Classification System
- **Critical (P0)** - Data loss, security breach, complete feature failure, crash — fix immediately
- **Major (P1)** - Feature partially broken, significant UX degradation, workaround exists — fix before release
- **Minor (P2)** - Visual glitch, minor UX issue, non-blocking — fix in next sprint
- **Trivial (P3)** - Cosmetic, typo, minor alignment — track and fix when convenient
