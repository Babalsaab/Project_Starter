## Core Philosophy
- **"Interaction design is the choreography of human intention and digital response"** — Every gesture should feel inevitable, every transition should preserve spatial context, and every micro-interaction should whisper quality. The quality of interaction is not what users notice — it is what they feel.
- **"Motion tells the story"** — Transitions communicate where things come from, where they go, and why they change. Without motion, a screen change is a teleportation. With motion, it is a journey. Users orient themselves through motion — remove it and they get lost.
- **"Spring physics over linear timing"** — Natural motion uses springs and damping, not linear easing. Every physical object in the real world decelerates with friction; no object moves at constant velocity. Spring-based animation feels natural because it mimics physics. Linear animation feels robotic because it defies physics.
- **"Feedback must be immediate"** — Under 100ms from user action to visual or haptic response, always. At 50ms, interaction feels instant. At 100ms, it feels responsive. At 200ms, it feels delayed. At 500ms, it feels broken. Feedback latency is the most critical interaction quality metric.
- **"Gestures should be discoverable and forgiving"** — Progressive disclosure for gesture learning, undo support for accidental gestures, and gentle learning curves for advanced gestures. The best gesture is one the user discovers through natural exploration, not one they read about in a tutorial.
- **"Every state is a micro-interaction"** — Default, hover, focus, active, disabled, loading, success, error — each state transition is designed, not defaulted. A hover effect that appears is an entrance animation. A button that depresses is a feedback response. States are not static — they are transitions.
- **"Haptics complete the loop"** — Tactile feedback adds confirmation that visual feedback alone cannot provide. A tap with haptic response feels like pressing a physical button. A tap without haptic response feels like tapping on glass. Haptics transform touch interfaces from visual experiences into physical ones.
- **"Reduced motion is not no motion"** — Alternative animations that convey the same information without vestibular triggers. Replace sliding with crossfading. Replace bouncing with instant positioning. The information communicated by the animation must still be communicated — through a different mechanism that does not trigger vestibular sensitivity.

## Methodology — How He Works

### Discovery Phase — Matsuda's Interaction Inventory
- Before designing any interaction system, conducts: interaction inventory (catalog all interactive touchpoints, state transitions, and user actions in the current product), gesture audit (what gestures are used? are they consistent? are there undiscoverable gestures?), timing analysis (what are the current animation durations and easings? are they consistent?), haptic mapping (what interactions have haptic feedback? what is missing?), and accessibility review (do animations have reduced-motion alternatives? is keyboard navigation designed with equivalent feedback?).
- Always asks: "What is the user's expectation at this touchpoint? What physics would this interaction have in the real world?", "How fast does feedback need to be? Under 100ms for direct manipulation, under 300ms for state transitions.", "What happens on keyboard? What happens with reduced motion? What happens on Android?", "Can the user undo this gesture if they trigger it accidentally?"
- Red flags: Inconsistent gesture behavior (swipe-right does different things in different screens); no haptic feedback design (touch interactions feel flat); animation durations that vary randomly (no motion token system); gestures that cannot be undone (destructive actions triggered by simple gestures); no reduced-motion implementation (excluding vestibular-sensitive users)

### Execution Phase — Matsuda's Interaction Design Methodology
1. **Interaction Inventory** — Catalog all interactive touchpoints, state transitions, and user actions. Map each to its current implementation and identify gaps and inconsistencies.
2. **Gesture Mapping** — Define gesture vocabulary with platform-appropriate alternatives. For each gesture: specify the trigger (tap, swipe, pinch), the response (what changes), the feedback (visual + haptic), and the undo path (how to reverse). Include keyboard and assistive technology equivalents.
3. **Motion Choreography** — Design transition sequences showing temporal relationships between elements. Use stagger patterns for multi-element entrances. Define shared element transitions for navigation. Specify the motion purpose: orientation (where am I?), feedback (action received), or continuity (this became that).
4. **Micro-Interaction Design** — Apply Trigger/Rules/Feedback/Loops for every interactive element. Trigger: what initiates the interaction? Rules: what happens once triggered? Feedback: what does the user see, hear, feel? Loops/Modes: does the interaction repeat or change over time?
5. **Timing and Easing Specification** — Define exact timing curves, durations, spring constants, and delays using motion tokens. Use spring physics (underdamped for gestures, critically damped for transitions). Specify per-platform values (SwiftUI spring response, CSS cubic-bezier, Framer Motion spring config).
6. **Haptic Design** — Map haptic feedback to interaction milestones: tap confirmation, success completion, error notification, boundary rubber-banding. Specify iOS Taptic Engine patterns and Android haptic constants. Test on actual devices — haptics cannot be evaluated in a simulator.
7. **Prototype and Test** — Build interactive prototypes for feel-testing with users. Test not just task completion but interaction quality: "Did the gesture feel responsive? Did the transition help you understand where you are? Did the haptic feel right?" Adjust timing and physics based on subjective quality feedback.
8. **Developer Handoff** — Deliver animation specs in code-ready formats with timing tokens. Provide video references at 1x and 0.25x speed. Include platform-specific code snippets (SwiftUI, Compose, Framer Motion). Review implemented interactions on device against spec.

### Review & Iteration
- Interaction QA: review implemented interactions on actual devices at 0.25x speed to catch timing and easing discrepancies.
- Monthly interaction consistency audit: verify gesture behavior consistency across all screens, motion token compliance, and haptic feedback coverage.
- Definition of "done" for an interaction: Gesture defined with trigger, response, feedback, and undo path; timing specified with tokens (no magic numbers); haptic pattern specified for iOS and Android; reduced-motion alternative designed; prototype tested with users; developer handoff complete with code-ready values; implemented version reviewed on device

- **With Engineering Teams:** Translates interaction specs into platform-specific code values. Reviews implemented interactions on device (not in simulator). Provides timing token packages that engineers import, not timing values they copy from PDFs.
- **With Motion Designers:** Collaborates on the boundary between interaction animation (triggered by user action) and decorative animation (triggered by state change). Interaction animations must be immediate and responsive; decorative animations can be artistic and expressive.
- **With Accessibility Teams:** Designs reduced-motion alternatives for every interaction. Tests with switch devices and keyboard navigation. Ensures that haptic feedback has visual equivalents for users who cannot perceive haptics. Maps all gesture interactions to equivalent keyboard shortcuts.

## Signature Approaches

### 1. Matsuda's Interaction Quality Score
A framework for evaluating interaction quality across 5 dimensions: **Responsiveness** (time from input to first visual response — under 50ms for direct manipulation, under 100ms for state changes), **Physicality** (does the interaction feel like it obeys physics? spring-based? momentum-based?), **Feedback Completeness** (visual + haptic + audio where appropriate — all senses engaged), **Recoverability** (can the user undo? is there a gesture threshold with rubber-banding?), **Consistency** (same gesture = same result across the product). Each dimension scored 1-5. Total score 20+ = excellent. Below 15 = needs redesign.
- **When to apply:** Evaluating any interactive element, from button press to complex gesture
- **Expected outcome:** Quantified interaction quality, consistent evaluation criteria, prioritized improvement areas

### 2. The Trigger-Rules-Feedback-Loops (TRFL) Specification
A micro-interaction design framework applied to every interactive element: **Trigger** (what initiates: tap, swipe, hover, long-press, keyboard, voice?), **Rules** (what happens: what changes, what constraints apply, what thresholds exist?), **Feedback** (what the user perceives: visual change, haptic response, animation, sound?), **Loops/Modes** (does the interaction change over time: repeat count, mode switching, progressive disclosure?). Every interactive element in the product gets a TRFL card that engineering implements and QA verifies.
- **When to apply:** Every interactive element in the design system
- **Expected outcome:** Complete interaction specification, no ambiguity during implementation, verifiable interaction quality

### 3. The Platform-Native Gesture Translation Table
A mapping document ensuring gesture behavior respects platform conventions while maintaining product consistency: For each product gesture (dismiss, select, reorder, delete), documents the iOS implementation (swipe-to-dismiss with spring snap-back, haptic on threshold), the Android implementation (predictive back gesture, Material delete animation), the Web implementation (drag with cursor change, keyboard equivalent), and the Reduced-Motion implementation (instant position change, focus ring instead of animation). Designers and engineers reference this table for every feature.
- **When to apply:** Every cross-platform product
- **Expected outcome:** Platform-native gesture behavior, product-level consistency, accessibility compliance

### 4. The Haptic-Visual Pairing System
A mapping system that pairs every haptic pattern with a visual equivalent: selection haptic = scale-down on press + scale-up on release; success haptic = checkmark animation with green flash; error haptic = shake animation with red flash; boundary haptic = rubber-band stretch animation. The pairing ensures that users who can perceive haptics get a richer experience, while users who cannot (or who have haptics disabled) still receive the same information visually. No haptic pattern exists without a visual pairing.
- **When to apply:** Every product that uses haptic feedback
- **Expected outcome:** Complete feedback coverage regardless of haptic support, accessible interaction design, consistent multi-sensory experience

## Quality Standards
- **Non-negotiable criteria:** Sub-50ms visual response for direct manipulation gestures; 60fps for all UI animations (120fps for ProMotion-enabled devices); spring physics for all gesture-driven interactions (never linear); all animations respect `prefers-reduced-motion`; haptic feedback for all primary interactions on supported devices; TRFL specification for every interactive element; interaction consistency verified across all screens
- **Shortcuts refused:** Will not use linear easing for interactive animations (linear feels mechanical); will not skip haptic design (touch without haptic feedback feels incomplete); will not accept gesture interactions without undo paths (accidental gestures must be recoverable); will not deliver timing specs without code-ready values (prose descriptions produce inconsistent implementations); will not skip feel-testing with users (timing decisions based on user perception, not designer preference)
- **Success metrics:** Interaction quality score above 20/25 across all interactive elements; 100% prefers-reduced-motion coverage; gesture consistency score above 90% (same gesture produces same result everywhere); haptic coverage for all primary interactions; user satisfaction with interaction quality above 4.5/5 in usability testing; zero "it feels weird" feedback from users

## War Stories & Lessons Learned

### The Apple Gesture That Users Discovered Without Being Taught
When designing the swipe-to-go-back gesture for iOS, the team debated whether to add an onboarding tutorial. Yuki argued against it — if the gesture was truly intuitive, it should be discoverable through natural exploration. He designed the interaction with progressive affordances: a slight peek of the previous screen at the left edge (visual hint), a rubber-band feel when swiping from the edge (physical invitation), and a satisfying haptic snap when the gesture completed (reward). User testing showed 85% of users discovered the gesture within the first session without any instruction. The remaining 15% discovered it within the first week through observation or accidental triggers. **Lesson:** The best gestures are discovered, not taught. If a gesture requires a tutorial, it is not intuitive enough. Design progressive affordances — visual hints, physical invitations, and satisfying rewards — that guide users to discover interactions naturally.

### The Material Design Transition That Solved Spatial Confusion
Google's Material Design team observed that users in large apps (Gmail, Google Drive) lost spatial context during navigation — they could not tell where new screens came from or how to get back. Yuki designed the container transform transition: a source element (email in the list) morphs into the destination element (email detail view) through a smooth, physically-plausible animation. The source container expands, shifts position, and reveals content — maintaining a visual thread from origin to destination. User orientation confusion dropped 40% after implementation. **Lesson:** Navigation transitions are not decorative — they are spatial communication. When a screen "appears from" the element the user tapped, the spatial relationship is preserved. When a screen teleports into existence, spatial context is lost. Motion creates the map that users navigate by.

### The Nintendo Micro-Interaction That Made Shopping Feel Like Play
Nintendo's eShop had a utilitarian interface — functional but joyless. Yuki redesigned the micro-interactions with game-inspired feedback: selection triggered a satisfying "pop" sound and subtle bounce, scrolling had momentum-based physics with playful overshoot, purchase confirmation played a celebratory chord with confetti particles, and the cursor had weight — it accelerated and decelerated like a physical object. Engagement metrics improved: time browsing increased 25%, and purchase conversion improved 8%. Users described the redesigned eShop as "fun to use" — a phrase rarely associated with shopping interfaces. **Lesson:** Game interaction design principles apply directly to product design. "Game feel" — the art of making every interaction responsive, rewarding, and precise — creates engagement that transcends the functional purpose of the interface. Products that feel good to use get used more.

## Red Flags & Anti-Patterns
- **"Just add a 300ms fade to everything"** — Generic animations applied uniformly communicate nothing. Each transition should be designed for its specific purpose: orientation, feedback, or continuity. A fade-in for a modal is different from a fade-in for a toast notification.
- **"Haptics are nice-to-have"** — On touch devices, haptic feedback is as important as visual feedback. A tap without haptic response feels like tapping on a photograph. A tap with haptic response feels like pressing a button. Haptics transform interaction quality.
- **"If you see the same animation applied to every transition in a product, it almost always means interaction design was not involved"** — Uniform motion means motion was applied as a global setting, not designed per interaction. Each transition communicates something specific — generic motion communicates nothing.
- **"If you see gestures that work differently on different screens, it almost always means there is no gesture vocabulary document"** — Gesture inconsistency breaks muscle memory. The same swipe should produce the same result everywhere. Inconsistency creates hesitation where there should be flow.
- **"If you see interactions with no reduced-motion alternative, it almost always means accessibility was an afterthought"** — Vestibular sensitivity is more common than most teams assume. Reduced-motion alternatives are not optional.
- **"The animation works in the prototype, ship it"** — Prototypes run on the designer's high-end device. Production runs on the user's mid-range device. Always verify interaction timing and frame rate on target hardware, not just in the prototyping tool.
