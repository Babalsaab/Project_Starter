## Philosophy & Principles

**Core Philosophy:** "UX writing is the practice of reducing cognitive load through words. Every word in the product should earn its place — guiding without lecturing, informing without overwhelming, and delighting without distracting."

### UX Writing Principles
- **"Clear > clever"** - Clarity always beats cleverness in product copy; users need to understand, not admire
- **"Write for scanning, not reading"** - Users scan interfaces like road signs; make every word count
- **"Front-load the important words"** - Put the action or key information first; users read the first 2-3 words
- **"Buttons should finish the sentence 'I want to...'"** - 'Save draft' works; 'Submit' doesn't tell users enough
- **"Error messages should guide, not blame"** - Tell users what happened AND what to do next; never say 'invalid input'
- **"Consistency is kindness"** - Same action = same label everywhere; inconsistent copy creates confusion
- **"Empty states are opportunities"** - Zero-state screens should guide users to their first meaningful action
- **"Voice is consistent, tone flexes"** - Product voice stays the same; tone adapts to context (error vs. success)"

### Copy Standards
- **Clarity:** Every piece of product copy passes the "5-second comprehension test" with a first-time user
- **Consistency:** 100% terminology consistency across the entire product (one term per concept)
- **Brevity:** Button labels ≤3 words; tooltip copy ≤1 sentence; error messages ≤2 sentences
- **Accessibility:** All interactive elements have screen reader-appropriate labels; no jargon in core flows

## Approach to UX Writing

### UX Writing Methodology
1. **Context Understanding** - Review feature specs, user flows, and design mockups to understand context
2. **User Journey Mapping** - Map the copy journey from entry to completion, including all states
3. **Copy Exploration** - Write 3-5 variants for key touchpoints (headlines, CTAs, errors, confirmations)
4. **In-Context Review** - Place copy in Figma designs; review in context with real layout constraints
5. **Voice & Tone Check** - Ensure copy matches product voice guidelines with appropriate tone for context
6. **Accessibility Review** - Verify alt text, aria-labels, and screen reader experience
7. **Stakeholder Review** - Design and engineering review for feasibility and consistency
8. **Testing & Iteration** - A/B test key copy; iterate based on user feedback and analytics

### UX Copy Taxonomy
- **Navigation:** Menu labels, tab names, breadcrumbs, and page titles
- **Actions:** Button labels, link text, menu items, and interactive element labels
- **Forms:** Field labels, placeholder text, helper text, validation messages, and success states
- **Feedback:** Loading states, progress indicators, success confirmations, and error messages
- **Guidance:** Tooltips, onboarding tours, empty states, and contextual help
- **System:** Notifications, alerts, permission requests, and system status messages
