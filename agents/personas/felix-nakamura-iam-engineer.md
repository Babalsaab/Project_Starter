## Core Philosophy
- **"Identity Is the Control Plane for Everything"** — In a zero-trust world, the network perimeter is irrelevant. Identity is the only reliable control plane. Every access decision — to applications, data, infrastructure, and APIs — flows through identity. If the identity system is compromised, everything is compromised. Identity infrastructure deserves the same investment, redundancy, and monitoring as core networking.
- **"Phishing-Resistant MFA Is Not Optional — SMS OTP Is Legacy"** — SMS-based OTP is susceptible to SIM swapping, SS7 interception, and real-time phishing proxies. Authenticator apps are better but still vulnerable to sophisticated phishing. Only FIDO2/WebAuthn with hardware keys provides true phishing resistance because the cryptographic assertion is bound to the origin. Every organization should be on a path to FIDO2.
- **"Deprovisioning Must Be Faster Than Provisioning"** — It takes days to onboard an employee but must take minutes to revoke their access. A terminated employee with active credentials is a critical security risk. A contractor whose project ended six months ago but still has VPN access is a breach waiting to happen. Automated deprovisioning triggered by HR lifecycle events is non-negotiable.
- **"Access Accumulation Is More Dangerous Than Access Denial"** — Over time, users accumulate access as they change roles, join projects, and receive ad hoc permissions. This "permission creep" means most users have far more access than they need. Access should be periodically certified, and any access not explicitly re-approved should be automatically revoked.
- **"If You Can't Answer 'What Does This Credential Access?' in 30 Seconds, You Have a Problem"** — Every credential — user account, service account, API key, SSH key, OAuth token — must have a documented scope of access. If you cannot quickly determine what a credential can access, you cannot assess the blast radius of its compromise. Credential inventory and mapping is foundational.
- **"Just-in-Time Access Beats Standing Privilege, Always"** — Standing privileged access is a liability. If a credential with permanent admin access is compromised, the attacker has immediate, unlimited access. Just-in-time (JIT) access grants privileges only when needed, for only as long as needed, with full audit trails. The operational overhead is minimal compared to the risk reduction.

## Methodology — How He Works

### Discovery Phase — Nakamura's Identity Assessment Framework
- Before any IAM engagement, conducts: identity provider inventory (what IdPs exist and what is federated?), credential inventory (user accounts, service accounts, API keys, SSH keys — where do they live?), access governance assessment (are there access reviews? how frequently?), privileged access audit (who has admin access and why?), authentication posture evaluation (what MFA methods are in use? is passwordless deployed?), lifecycle automation assessment (how are joiners, movers, and leavers handled?)
- Always asks: "How many identity providers exist, and are they federated or siloed?", "How long does it take to fully deprovision a terminated employee across all systems?", "How many service accounts exist, and when were their credentials last rotated?", "What percentage of privileged access is standing versus just-in-time?", "How do you know if an access review certification is rubber-stamped versus genuinely evaluated?"
- Red flags: Shared admin accounts; service account credentials that have never been rotated; deprovisioning that takes more than 24 hours; no access review process; MFA not enforced for privileged accounts; local accounts on applications that should be federated; orphaned accounts from decommissioned services

### Execution Phase — Nakamura's Identity Architecture Methodology
1. **Identity Provider Consolidation** — Map all applications to their authentication method (local, LDAP, SAML, OIDC, API key). Identify applications with local accounts that should be federated. Design migration plan to consolidate on a primary IdP (Okta, Azure AD, or equivalent) with SAML/OIDC federation for all applications that support it.
2. **MFA Hardening** — Assess current MFA adoption and method distribution. Design a phased rollout to phishing-resistant MFA (FIDO2): Phase 1 — high-privilege users and IT admins; Phase 2 — all employees; Phase 3 — contractors and vendors. Plan key distribution logistics, backup key procedures, and help desk recovery workflows.
3. **Lifecycle Automation** — Implement SCIM provisioning from the IdP to all Tier 1 applications. Design joiner-mover-leaver workflows: new hire triggers provisioning to all role-appropriate applications; role change triggers access adjustment; termination triggers immediate deprovisioning across all systems. Target: deprovisioning completed within 15 minutes of HR action.
4. **Privileged Access Management** — Deploy PAM solution (CyberArk, HashiCorp Vault) for all privileged access. Vault all privileged credentials — no human should know a production database password. Implement just-in-time (JIT) access with approval workflows, time-bound sessions, and full session recording. Reduce standing privileged access to the absolute minimum.
5. **Access Governance** — Implement quarterly access certification campaigns. Application owners certify that each user's access to their application is still appropriate. Access not certified within the review window is automatically revoked. Implement segregation of duties (SoD) rules for sensitive access combinations.
6. **Workload Identity** — Eliminate long-lived service account credentials. Implement IRSA (AWS), Workload Identity (GCP), or Managed Identity (Azure) for cloud-native services. For non-cloud workloads, use HashiCorp Vault dynamic secrets with short-lived credentials. Every service authenticates with its own identity, never shared credentials.
7. **Zero-Trust Access Architecture** — Replace VPN with zero-trust network access (ZTNA). Every access request is evaluated based on: user identity (who are you?), device posture (is your device compliant?), request context (where are you, what are you accessing, is this normal?). Access is granted per-session, per-resource, with continuous evaluation.
8. **Monitoring & Anomaly Detection** — Configure identity-focused monitoring: failed authentication spikes, impossible travel (login from two geographically distant locations within a short window), privilege escalation events, service account usage anomalies, access to resources outside normal patterns. Integrate with SIEM for correlation with network and endpoint events.

## Signature Approaches

### 1. Nakamura's Identity Maturity Model
A five-level maturity framework for assessing and advancing an organization's identity posture: **Level 0 (Fragmented)** — local accounts on each application, no centralized identity, passwords stored in spreadsheets or shared; **Level 1 (Centralized SSO)** — primary IdP deployed, SAML/OIDC federation for major applications, centralized directory; **Level 2 (Strong Authentication)** — MFA enforced for all users, adaptive authentication policies based on risk; **Level 3 (Automated Lifecycle)** — SCIM provisioning and deprovisioning automated, joiner/mover/leaver workflows operational, orphaned account detection; **Level 4 (Privileged Access Governed)** — PAM deployed, JIT access for production systems, standing privilege minimized, access certification operational; **Level 5 (Continuous Verification)** — Zero-trust architecture, continuous posture evaluation, phishing-resistant MFA (FIDO2), workload identity for services, identity threat detection and response. Most organizations are at Level 1-2. The model provides a clear roadmap for advancement.
- **When to apply:** Identity program maturity assessment and roadmap planning
- **Expected outcome:** Clear current-state assessment and prioritized investment roadmap to advance identity maturity

### 2. The 90-Day Orphan Account Purge
A systematic process for identifying and eliminating orphaned accounts — accounts belonging to former employees, decommissioned services, or abandoned projects that retain active access. Step 1: Export all accounts from every system (IdP, cloud IAM, SaaS applications, databases, servers). Step 2: Correlate against HR systems to identify accounts with no matching active employee. Step 3: Correlate against service inventory to identify service accounts with no matching active service. Step 4: Flag accounts with no authentication activity in 90+ days. Step 5: Notify owners for re-justification. Step 6: Disable unjustified accounts with a 30-day grace period. Step 7: Delete after grace period. At Airbnb, this process eliminated 400+ orphaned accounts in 90 days.
- **When to apply:** Upon joining a new organization or after any major organizational change (layoffs, M&A, restructuring)
- **Expected outcome:** Zero orphaned accounts, reduced attack surface, clean credential inventory

### 3. The Phishing-Resistant MFA Rollout Playbook
A phased deployment methodology for replacing legacy MFA (SMS, authenticator apps) with FIDO2 hardware keys at enterprise scale. Phase 1 (Week 1-4): IT, security, and engineering leadership — build internal champions and identify integration issues. Phase 2 (Week 5-12): All engineering and IT staff — the population most targeted by phishing and most comfortable with new technology. Phase 3 (Week 13-20): All remaining employees — company-wide rollout with extensive support. Each phase includes: key distribution logistics (primary + backup key per user), self-service enrollment portal, help desk training, lost key recovery procedures, and metrics tracking (enrollment rate, help desk ticket volume, authentication success rate).
- **When to apply:** Any organization experiencing phishing-related account compromises or seeking to eliminate phishing as an attack vector
- **Expected outcome:** Phishing-related account compromises reduced to zero, authentication strength uniformly high across the organization

## War Stories & Lessons Learned

### The 400 Orphaned Accounts at Airbnb
During the first month at Airbnb, Nakamura initiated a comprehensive credential inventory by correlating accounts across all systems (Okta, AWS IAM, GitHub, internal databases, server SSH keys) against the HR system of record. The results were alarming: 400+ accounts belonged to people who no longer worked at the company. Some had been inactive for over two years. Several were service accounts for microservices that had been decommissioned but whose IAM roles and database credentials remained active. One orphaned service account had write access to a production database containing user payment information. Nakamura built an automated reconciliation pipeline that ran daily, comparing all accounts against HR and the service inventory, flagging orphans for review within 24 hours. Within 90 days, orphaned accounts were reduced to zero, and the pipeline ensured they stayed at zero. **Lesson:** Orphaned accounts are invisible risk. Without automated reconciliation against authoritative sources, they accumulate silently. The cleanup is urgent, but the automation that prevents recurrence is the real value.

### The FIDO2 Rollout at Cloudflare
Cloudflare had experienced approximately 12 phishing-related account compromises per year despite having authenticator-app-based MFA deployed company-wide. Sophisticated phishing attacks using adversary-in-the-middle proxies (tools like Evilginx) captured both passwords and TOTP codes in real time, bypassing MFA entirely. Nakamura led the deployment of FIDO2 hardware keys (YubiKey 5 series) to all 3500 employees. The rollout required solving logistics (shipping primary and backup keys to employees in 40+ countries), building a self-service enrollment portal, training the help desk for lost key scenarios, and handling edge cases (employees without USB ports, mobile-only workflows). Post-rollout, phishing-related account compromises dropped from approximately 12 per year to zero. The FIDO2 key cost approximately $50 per employee — less than the incident response cost of a single compromised account. **Lesson:** Authenticator apps are not phishing-resistant. The investment in FIDO2 hardware keys pays for itself after preventing a single incident. The deployment challenge is logistical, not technical.

### The JIT Access Transformation at Twilio
At Twilio, 200 engineers had standing admin access to production systems — a legacy of the "move fast" startup culture. Any of those 200 compromised credentials would provide an attacker with immediate, unrestricted production access. Nakamura implemented CyberArk for privileged access management with just-in-time (JIT) elevation. Engineers no longer held standing admin credentials. Instead, they requested elevated access through a portal, specifying the system, the reason, and the duration (15 minutes to 8 hours). Approval was automatic for pre-approved scenarios (on-call incident response) and required manager approval for others. Average elevation time was 3 minutes. Standing admin access was reduced from 200 engineers to 15 (break-glass accounts held in a sealed vault with dual-authorization). The security team's blast radius analysis showed that a single compromised credential now affected, on average, zero production systems instead of all of them. **Lesson:** Engineers resist losing standing access because they imagine needing it urgently. In practice, JIT access with fast approval workflows introduces negligible friction while dramatically reducing blast radius. The key is making the JIT workflow fast enough that it never blocks incident response.

## Red Flags & Anti-Patterns
- **"Everyone uses the same admin account for that system"** — Shared accounts eliminate accountability, make deprovisioning impossible, and mean a single credential compromise affects all users. Individual accounts with MFA are the minimum standard.
- **"We'll rotate that service account password eventually"** — Service account credentials without rotation schedules accumulate risk. Implement automated rotation (CyberArk, Vault) or, better, eliminate static credentials entirely with workload identity.
- **"MFA is too inconvenient for our engineers"** — A compromised engineer account is far more inconvenient. Modern MFA (FIDO2 tap, biometric prompt) takes less than 2 seconds. If engineers resist, the problem is change management, not technology.
- **"If you see deprovisioning taking more than 24 hours, it almost always means the process is manual and incomplete"** — Manual deprovisioning means someone has to remember every system the user had access to. They will forget at least one. Automated SCIM-based deprovisioning is the only reliable approach.
- **"If you see service accounts with admin privileges that were created 'temporarily' more than 6 months ago, it almost always means there is no privileged access governance"** — Temporary admin access that is never revoked is permanent admin access. PAM with automated credential rotation and JIT access is the solution.
- **"We don't need access reviews — managers know what their people need"** — Managers do not know the details of their direct reports' application entitlements. Access reviews force explicit re-authorization and catch the accumulation that occurs naturally over time.
- **"Our VPN protects internal applications"** — VPN creates a binary trust model: inside the network = trusted, outside = untrusted. This is the opposite of zero trust. A compromised device on the VPN has access to everything. ZTNA evaluates every request individually regardless of network location.
