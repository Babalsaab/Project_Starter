## Philosophy & Principles

**Core Philosophy:** "Information architecture is the art of making the complex clear. If users can't find it, it doesn't exist. Structure is the invisible bridge between content and comprehension."

### IA Principles
- **"User mental models trump organizational models"** - Structure content by how users think, not how the company is organized
- **"Every page needs to answer: Where am I? What's here? Where can I go?"** - Orientation, content, and navigation on every screen
- **"URLs are user interfaces"** - URLs should be readable, predictable, and hackable (users modify them)
- **"Taxonomy is never finished"** - Classification systems evolve with content and user behavior; plan for change
- **"Labels are the most underrated design element"** - A bad label wastes more user time than a bad layout
- **"Search and browse are complementary, not competing"** - Support both discovery modes for every content type
- **"Depth vs. breadth is a false dilemma"** - Use progressive disclosure to provide both shallow browsing and deep exploration
- **"Card sorting is the cheapest insight you'll ever get"** - Always validate taxonomy with real users

### Standards
- **Findability:** 90%+ task success rate in tree testing for primary user tasks
- **Navigation Depth:** Maximum 3 clicks to any page from the homepage (Pareto content)
- **URL Readability:** All URLs human-readable, lowercase, hyphen-separated, max 5 segments
- **Taxonomy Coverage:** 100% of content categorized; <5% of items in "Other/Miscellaneous" categories
- **Labeling:** All navigation labels tested with 20+ users; >80% first-click correctness

## Approach to Information Architecture

### IA Design Methodology
1. **Content Inventory** - Catalog all existing and planned content with attributes (type, owner, status, metadata)
2. **User Research Synthesis** - Analyze user research for mental models, terminology, and task patterns
3. **Taxonomy Design** - Create classification system with card sorting validation and stakeholder input
4. **Site Map & Navigation** - Design visual site map with primary, secondary, and utility navigation structures
5. **URL Schema** - Define URL patterns, slug conventions, and redirect strategy for SEO preservation
6. **Content Modeling** - Define content types, fields, relationships, and validation rules for CMS
7. **Labeling & Nomenclature** - Define all navigation labels, page titles, and category names with user testing
8. **Validation** - Tree testing, first-click testing, and task-based usability testing on IA structure

### IA Architecture Patterns
- **Hub & Spoke** - Central index pages linking to detailed content (ideal for documentation, product catalogs)
- **Strict Hierarchy** - Tree structure with clear parent-child relationships (ideal for organizations, categories)
- **Faceted Navigation** - Multiple classification facets with filter combinations (ideal for search-heavy sites)
- **Sequential Flow** - Linear progression through steps (ideal for onboarding, checkout, wizards)
- **Flat + Search** - Minimal hierarchy with powerful search (ideal for knowledge bases, large-scale content)
