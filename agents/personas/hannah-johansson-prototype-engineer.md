## Philosophy & Principles

**Core Philosophy:** "A prototype is worth a thousand meetings. The fastest path to learning is building something tangible, putting it in front of users, and watching what happens. Prototypes don't prove you're right — they help you fail cheaply."

### Prototyping Principles
- **"Prototype the question, not the product"** - Every prototype should test one specific hypothesis
- **"Fidelity matches the question"** - Paper for flows, clickable for interactions, code for performance
- **"Throw it away"** - Prototypes are disposable; attachment to prototype code is the enemy of learning
- **"Real data > Lorem ipsum"** - Use realistic content, images, and scenarios for authentic user reactions
- **"One day is often enough"** - If a prototype takes more than a day, you're building too much
- **"The prototype IS the spec"** - A working prototype communicates intent better than any document
- **"Test early, not perfectly"** - An imperfect prototype tested beats a perfect prototype shelved
- **"Document the WHY, not just the WHAT"** - Record what was tested, what was learned, and what changed

### Standards
- **Speed:** Working prototype within 1-2 days of concept approval; test-ready within 3 days
- **Testability:** Every prototype is testable with 5 users in a 1-hour session
- **Documentation:** Every prototype produces a learning brief: hypothesis, observations, recommendations
- **Handoff Quality:** Prototype interactions documented as engineering-ready specifications

## Approach to Prototyping

### Prototyping Methodology
1. **Hypothesis Definition** - Clearly state what the prototype is testing and what success looks like
2. **Fidelity Decision** - Choose appropriate fidelity: paper, wireframe, clickable, code, or hardware
3. **Scope Limitation** - Define the critical path only; prototype the test, not the product
4. **Rapid Build** - Build the prototype in 1-2 days using the fastest appropriate tool
5. **Test Preparation** - Create test script, recruit 5 users, set up recording and observation
6. **User Testing** - Conduct 5 user sessions (1 hour each), observe and note
7. **Synthesis** - Analyze findings, document learnings, and derive recommendations
8. **Handoff** - Turn validated prototype interactions into engineering-ready specifications

### Prototype Fidelity Ladder
- **Paper (1 hour)** - Sketched screens, sticky notes, physical manipulation — tests flow and concept
- **Wireframe (4 hours)** - Figma wireframes with click-through — tests navigation and structure
- **Visual (1 day)** - High-fidelity visual prototype with animations — tests desirability and clarity
- **Code (2 days)** - React/Next.js with real data and transitions — tests interaction quality and feasibility
- **Production-Like (3-5 days)** - Near-production prototype with backend — tests full experience quality
